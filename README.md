# yahtzee-solver

快艇骰子（Yahtzee）**精确最优决策求解器**。不是启发式，不是查表近似——
对整局游戏做后向归纳，算出每一步的期望最优解，以及任意局面下的**胜率**。

> [English README](README.en.md)

支持多套规则：

| 预设 | 说明 | 栏数 | 开局最优期望 |
|---|---|---|---|
| **`clubhouse`** | 《世界游戏大全 51》版 | 12 | **191.77** |
| **`standard`** | 标准 Yahtzee（Hasbro） | 13 | **245.91** |

规则写在 `config.json` 里，可以直接改；也可以自己新增一套。

## 快速开始

```bash
git clone https://github.com/Macyrate/yahtzee-solver
cd yahtzee-solver
python3 -m venv .venv && ./.venv/bin/pip install numpy
./.venv/bin/python advise.py adv "1 3 3 3 4" 2
```

（仓库里已经带了建好的 `tables.npz`，clone 下来就能用，不用先建表。）

> **环境**：Python 3.9+ 和 numpy（见 `requirements.txt`），没有别的依赖。
> 版本影响建表速度：Python 3.12 + numpy 2.5 约 4 秒，Python 3.9 + numpy 2.0 约 8 秒。
> 另外 numpy < 2.5 在 macOS 上会从 BLAS 抛出 `divide by zero encountered in matmul`
> 一类的**假警告**（纯随机数组也能复现，结果不受影响），代码里已定向屏蔽。

## 命令

假设已经 `source .venv/bin/activate`。

### 看当前规则 / 开新局

```bash
python advise.py rules          # 打印规则表 + 三个期望基准值
python advise.py reset          # 清空记分卡
```

### 每掷一次骰子，问保留

```bash
python advise.py adv "1 3 3 3 4" 2
```

第二个参数是**剩余重投次数**：刚掷完第一次给 `2`，第二次给 `1`，第三次（该记分了）给 `0`。

输出会给出最优保留、期望总分，以及次选方案差多少分。

### 记分

```bash
python advise.py take 3点 "1 2 3 3 3"
```

分数由骰子自动算出，同时更新上区进度和剩余最优期望。

### 算胜率

```bash
python pwin.py 8 6000 "1点=2,2点=8,3点=12,机会=22"
```

| 参数 | 含义 |
|---|---|
| 1 | 你剩余回合数（= 你未填的栏数） |
| 2 | 蒙特卡洛样本数（默认 3000；6000 约 3 秒，误差 ±0.6%） |
| 3 | **对方的完整记分卡**，格式 `栏位=分,…`；全空传 `""` |

我方的记分卡从 `state.json` 读。

> **口径提醒**：如果你刚打完这一回合、对方还没掷，那么「你剩 N 回合、对方剩 N+1 回合」，
> 算出来的胜率会**偏保守**。等对方也掷完，两边才在同一基准上。

### 换规则

```bash
python use.py                   # 列出所有预设，标出当前的
python use.py standard          # 切到标准 Yahtzee 并重建表（约 10 秒）
python use.py clubhouse         # 切回来（约 5 秒）
```

### 自检

```bash
python verify.py                # 用真实随机骰子独立蒙特卡洛校验三个基准
python verify.py 32 56 20       # 校验任意一个中间局面 (ru, s, rl)
python advise.py sim 20000      # 全盘模拟对照
```

## 自定义规则

`config.json` 就是当前生效的规则集。每栏声明一个**规则**加参数：

```json
{
  "preset": "my-variant",
  "title": "我的变体",
  "bonus": { "threshold": 63, "value": 35 },
  "categories": [
    { "name": "1点", "kind": "upper", "rule": "upper", "face": 1 },
    { "name": "四条", "kind": "lower", "rule": "n_kind",
      "params": { "n": 4, "score": "sum" } },
    { "name": "葫芦", "kind": "lower", "rule": "full_house",
      "params": { "score": 25 } }
  ]
}
```

**可用规则**

| `rule` | 命中条件 | 参数 |
|---|---|---|
| `upper` | 总是 | `face`（1–6），得分 = 点数 × 个数 |
| `n_kind` | 至少 n 颗相同 | `n`，`score`（`"sum"` 或固定分） |
| `full_house` | 3+2 或五颗相同 | `score`（`"sum"` 或固定分） |
| `straight` | 有 `length` 个连续点数 | `length`、`score` |
| `all_same` | 五颗相同 | `score` |
| `sum` | 总是 | 无，得分 = 五颗总和 |

**约束**：`kind: "upper"` 的栏必须排在前面（它们的合计决定奖励）；栏的顺序就是求解器掩码里的位序。
改完跑 `python solve.py` 重建表（不重建会报错提示）。

`presets/` 里放了两个现成例子，`use.py` 做的就是「复制文件 + 重建表」。

## 它是怎么算的

状态空间是

```
(还没填的上区掩码, 上区当前小计, 还没填的下区掩码)  ×  252 种骰面组合
```

252 = 五颗骰子的全部**多重集合**（不是 6⁵ = 7776 种有序结果，因为骰子不可区分）。
一个回合内的三次投掷用同一个「保留 → 重投」转移张量处理。

Clubhouse 版约 17.6 万个状态、5 秒建表；标准版 13 栏约 35 万个状态、10 秒。

## 它算得准吗

全部经过**独立**蒙特卡洛校验——模拟用真实随机骰子 + 独立的算分路径，
所以能抓出「自洽但错误」的 DP 抓不到的问题。

| 模式 | 项目 | DP | 模拟 |
|---|---|---|---|
| clubhouse | 全局 | 191.774 | 192.37 ± 0.70 |
| clubhouse | 上区单练 | 71.952 | 71.82 ± 0.45 |
| clubhouse | 下区单练 | 88.660 | 87.89 ± 0.47 |
| standard | 全局 | 245.905 | 245.47 ± 0.72 |
| standard | 上区单练 | 71.952 | 71.82 ± 0.45 |
| standard | 下区单练 | 140.030 | 140.07 ± 0.56 |

另外，加入多规则支持**重构前后结果逐位一致**。
标准模式的计分表也逐手核对过（`n_kind` / `full_house` / `straight` / `all_same`
在边界牌面上的取值，例如 `5 5 5 5 5` 同时算三条 25、四条 25、葫芦 25、快艇 50）。

**已知限制**：标准模式**不含 Yahtzee bonus**（首个快艇之后再掷出快艇加 100 分）。
那需要把「快艇是否已用」加进状态维度，状态空间会再翻一倍。
所以这里的 245.91 低于公开的最优值 254.59——差值 8.68 正是 Yahtzee bonus 的贡献。

## 两个反直觉结论

**1. 别拿高价值栏位换便宜分。**

`1 2 4 6 6` 这手牌里，「记 6点 = 12 分」比「记 1点 = 1 分」**差 10 分期望**。
因为 6点 是上区最大的一块（上限 30），把它花在 12 分上会让 +35 奖励的概率从
**54.2% 崩到 12.1%**（这两个数字是对两个后续局面各自跑 8000 局实测出来的）。

同理：`4 4 4 4 1` 该记 4点 = 16 而不是四条 = 17；`4 6 6 6 6` 该记
四条 = 28 而不是机会 = 28（差 15.1 分）。

**2. 该放弃的栏位要趁早放弃。**

`2 4 4 6 6` 硬追大顺成功率只有 16%，不如把这一掷用来把机会栏做大（约 24 分），
下一回合再从零打大顺——从零打反而有 26%，更高。

## 前提与免责

- 模型假设**双方都按期望分最大化**打。对手乱打的话，你的实际胜率会**高于**算出来的数字。
- 求解器给的建议是**期望分最优**，不是**胜率最优**。绝大多数时候两者一致；
  但当你大幅落后、必须搏高方差时，期望最优未必是胜率最优。
- 骰子必须是公平的。这条我没法验证。
